# Security Policy

## Supported versions

Security fixes are provided for the current stable release and the latest beta release.

| Version | Supported |
| --- | --- |
| 2.0 beta | Yes |
| 1.1.x | Yes |
| 1.0.x | No |
| Earlier versions | No |

Please confirm that an issue still occurs with the newest applicable release before reporting it.

## Reporting a vulnerability

Please report suspected security vulnerabilities privately through [GitHub's private vulnerability reporting](https://github.com/adityav0hra/WarpTab/security/advisories/new).

Do not disclose the vulnerability in a public issue, discussion, or pull request before a fix is available. Include, when possible:

- The affected WarpTab version and macOS version
- A clear description of the vulnerability and its potential impact
- Steps or a minimal proof of concept that reproduces the issue
- Any suggested mitigation or fix

You should receive an acknowledgement within three business days and a status update within seven business days. Resolution time will depend on severity and complexity. Please allow a reasonable remediation period before public disclosure.

Reports about ordinary bugs, feature requests, or behavior that has no security impact should use the repository's public issue tracker instead.

## Scope

Security reports may cover WarpTab's application code, release artifacts, update or installation instructions, permissions handling, window metadata, keyboard-event handling, and repository automation.

## Safe-harbor intent

Good-faith research that avoids privacy violations, data loss, service disruption, and access beyond what is necessary to demonstrate the issue will not be pursued by the project. This statement does not authorize testing against systems or data belonging to other people.

## Bug bounties

WarpTab does not currently offer a paid bug-bounty program.
